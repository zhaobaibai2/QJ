# 10 优化路线：结果还没到最好时怎么迭代

当前状态不是“失败”，而是典型的安全 RL 工程论文中期状态：主方法已能跑通，但 high-density safety、模块贡献和最终协议还没收敛。优化目标应该是先让证据稳定，再追求更高结果。

## 当前瓶颈判断

| 现象 | 证据 | 判断 |
|---|---|---|
| 中密度表现稳定 | proposed 14 seeds 在 density 0.08 success 0.747±0.039 | 主任务可支撑论文。 |
| 高密度碰撞高 | density 0.15 collision 0.414，success 0.467 | 主要优化方向。 |
| risk 是主要增益来源 | seed0 risk/proposed 远优于 baseline/curriculum | reward/guard 机制有效，但需要拆分。 |
| curriculum 贡献不确定 | seed0 density 0.08 risk≈proposed | 不能继续盲目夸课程。 |
| defensive 有潜力 | ttc12/v18 seed25 high density success 0.66/collision 0.18 | 值得固定参数多 seed。 |

## 优化原则

1. 一次只改一个机制，不要同时改 reward、horizon、speed、curriculum gate。
2. 每次调参先用 seed0 + 20 episodes 快筛，再用 3 seeds + 50 episodes 验证。
3. 所有筛查结果标记为 exploratory，只有 fixed protocol 多 seed 才能进主表。
4. 不要为了 density 0.15 牺牲 density 0.08 太多。中密度是主任务，高密度是 stress test。
5. 优化目标不要只看 success，要同时看 collision、cost、route、speed、episode length。

## 从当前结果继续提升的 5 条路线

### 路线 1: 固定 ttc12/v18 做 defensive 主方法

优先级最高。

为什么：

- 当前最强安全改进证据来自 ttc12/v18。
- 与 ISCSIC 的 safe control/autonomous systems 最契合。

下一步：

1. 修复 defensive 脚本 Python 路径。
2. 写 `evaluate_from_config.py`，保证用 run config 评估。
3. 补 seed24 评估。
4. 跑 seed26/27，`n_envs=4`。
5. 统计 mean±std。

成功标准：

| density | 目标 |
|---:|---|
| 0.08 | success ≥ 0.80，collision ≤ 0.10 |
| 0.15 | success ≥ 0.55，collision ≤ 0.30，cost ≤ 0.35 |

如果达不到：

- defensive 只作为探索性安全层，不放 abstract。

### 路线 2: 拆分 reward 和 action guard

优先级很高，因为它决定创新点是否站得住。

问题：

当前 `risk_reward=True` 同时启用 reward shaping 和 action guard。审稿人会认为不清楚提升来自哪里。

改法：

- `use_risk_reward`: 控制 reward 里的 TTC/lane/smooth/cost/progress。
- `use_action_guard`: 控制 TTC/overspeed 改动作。

建议实验：

| 设置 | 目的 |
|---|---|
| PPO | baseline |
| Reward-only | 证明 dense reward 是否有效 |
| Guard-only | 证明规则层是否单独有效 |
| Reward+Guard | 完整机制 |

成功标准：

- Reward-only 比 PPO 明显好，说明学习信号有价值。
- Guard-only 降低 collision，但可能牺牲 speed/success。
- Reward+Guard 最好或 Pareto 最好。

### 路线 3: 课程 gate 微调

优先级中等。只有在 risk vs proposed 多 seed 显示课程弱时再调。

当前风险：

- 课程过早进入 hard 可能导致训练不稳。
- demotion 开关在 run config 中为 True，但 README 曾写单调升级，需要统一。

可调参数：

| 参数 | 当前 run | 调整方向 |
|---|---:|---|
| `stage2_success` | 0.50 | 若过早进入 hard，提高到 0.55/0.60。 |
| `stage2_cost` | 0.30 | 若高密度碰撞多，降低到 0.25。 |
| `demote_grace_episodes` | 20/60 | 若频繁震荡，提高。 |
| `allow_demote` | True/False 不一致 | 最终协议必须固定一种。 |

建议：

- 投稿版本优先固定 `allow_demote=False`，更容易解释。
- 如果当前 best run 来自 `allow_demote=True`，论文必须写 adaptive promotion/demotion，不要写 monotonic。

### 路线 4: reward 权重小范围搜索

优先级中等。不要大网格，4070S 不适合。

只筛三组：

| Setting | ttc | cost | target_speed | 预期 |
|---|---:|---:|---:|---|
| current | 4 | 30 | 20 | 原始 RAC-PPO |
| defensive-light | 6 | 40 | 18 | 平衡成功和碰撞 |
| defensive-strong | 8 | 50 | 16 | 降碰撞，可能慢 |

每组先 seed0、20 episodes。只把最有前途的一组扩展到 3 seeds。

不要做：

- 同时搜索 10 个阈值。
- 只看 density 0.15 挑参数。
- 用 test set 大量调参后再报告同一 test set 最优。

### 路线 5: 失败案例驱动修正

优先级高，但成本低。

从 failed episodes 提取：

- collision 前 5 秒的 min_ttc。
- speed。
- action throttle/brake。
- lane deviation。
- route completion。

按失败类型聚类：

| Failure | 可能原因 | 修正 |
|---|---|---|
| high-speed curve out-of-road | target speed 太高或 lane penalty 弱 | 降 target speed / 提 lane penalty |
| rear-end collision | TTC threshold 太低或 brake 不够早 | 提 ttc threshold / soft braking |
| stuck low speed | penalty 太强或 progress 太弱 | 提 progress / 降 idle penalty |
| late collision after lane change | 只看前向 TTC 不够 | 加 lateral TTC 或 nearby vehicle risk |

这比盲目调参更有论文价值，因为可以写成 failure analysis。

## 4070S 下的优化节奏

### 快筛阶段

- timesteps: 300k 或 500k。
- episodes: 20。
- seeds: 只用 seed0。
- 目的：判断方向是否值得。

### 确认阶段

- timesteps: 1M。
- episodes: 50。
- seeds: 0/1/2 或新 seed 24/25/26。
- 目的：进入论文主表。

### 稳定性阶段

- 对最终方法可以用更多 seeds。
- 对 baseline 不必超过 3 seeds，除非 reviewers 要求。

## 优化后论文 claim 决策树

| 实验结果 | 论文写法 |
|---|---|
| risk 稳定优于 baseline，课程弱 | 论文主打 risk-aware reward，课程作为 training schedule。 |
| risk + curriculum 稳定优于 risk | 主打 RAC-PPO 完整框架。 |
| defensive 明显降 collision 但 success 小降 | 主打 safety-efficiency tradeoff。 |
| defensive 同时提 success 和降 collision | 可把 Defensive RAC-PPO 放主方法。 |
| 消融差异小 | 降低机制 claim，强调工程框架和评估发现。 |

## 不建议继续投入的方向

| 方向 | 为什么 |
|---|---|
| 现在上 CPO/复杂 safe RL baseline | 实现和调参周期长，4070S 下时间风险高。 |
| 追求 density 0.15 成功率 0.90 | 当前证据离得较远，容易过拟合或浪费时间。 |
| 同时补 SAC、多 safe RL、多 simulator | 范围过大，ISCSIC 不需要。 |
| 用旧 `final_paper_results` 继续写 | 汇总不全，会造成论文和结果错位。 |

## 最终可接受结果边界

ISCSIC 投稿不要求所有指标“最好”，但要求故事自洽。可以接受的最终状态：

- 主表：RAC-PPO 在 0.08 密度稳定优于 baseline，安全事件低。
- 压力测试：0.15 密度明确暴露 learned policy 的碰撞瓶颈。
- Defensive：能证明 shield 降低 collision/cost，即便 success 不是最高。
- 消融：至少 TTC 或 action guard 有清楚贡献。
- 论文：诚实承认仿真、启发式和 high-density limitation。

这比继续追一个不稳定的最高 seed 更容易被审稿人接受。
