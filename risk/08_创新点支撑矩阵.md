# 08 创新点支撑矩阵

这份文件回答“创新点到底靠什么支撑”。每个创新点都分成：概念新意、当前证据、还缺什么、论文里怎么写、审稿攻击怎么防。

## 创新点总览

| 创新点 | 推荐保留 | 当前强度 | 最关键补强 |
|---|---|---:|---|
| C1 风险感知密集奖励 | 是 | 7/10 | reward-only/no-action-guard 消融，`wo_ttc`。 |
| C2 Outcome-gated curriculum | 是，但降调 | 5/10 | risk vs proposed 多 seed，高密度和课程阶段曲线。 |
| C3 Defensive TTC/overspeed shield | 是，作为增强版 | 6/10 | fixed ttc12/v18 三种子、intervention rate。 |
| C4 多密度未见地图评价协议 | 是，作为实验贡献 | 6/10 | 更新 final summary，明确 density 是 difficulty axis。 |
| C5 4070S 可复现轻量工程 | 可作为工程特点 | 5/10 | 记录 n_envs=4、耗时、脚本、config manifest。 |

## C1 风险感知密集奖励

| 维度 | 内容 |
|---|---|
| 一句话 | 将碰撞前 TTC、车道偏离、控制平滑和事件 cost 转化为可学习的密集安全信号。 |
| 不是新在哪里 | TTC、reward shaping、安全 cost 都有先例。 |
| 新意在哪里 | 在 MetaDrive PPO 决策控制中把这些信号和 route progress/overspeed 一起落成可复现实验协议。 |
| 当前证据 | seed0 中 risk/proposed 远优于 baseline/curriculum；density 0.15 risk success 0.42 vs baseline 0。 |
| 还缺 | reward shaping 和 action guard 目前耦合，不能完全证明 reward 本身贡献。 |
| 必补实验 | `reward_only`、`guard_only`、`wo_ttc`。 |
| 可写 claim | Risk-aware shaping provides early safety feedback and is the dominant source of performance improvement in our MetaDrive setting. |
| 不能写 | This is the first TTC reward or a formally safe reward. |
| 审稿攻击 | “这只是手工 reward engineering。” |
| 防御 | 承认 lightweight engineering，但用多密度、多 seed、消融说明它在安全控制场景中有效且可复现。 |

## C2 Outcome-gated curriculum

| 维度 | 内容 |
|---|---|
| 一句话 | 不用固定时间表，而用最近 episode 的 route completion、success 和 cost 决定难度推进。 |
| 不是新在哪里 | curriculum learning 本身不是新概念。 |
| 新意在哪里 | 用安全结果和路线完成共同控制交通密度、道路复杂度和 accident probability。 |
| 当前证据 | 代码实现完整；seed0 下 proposed 在 density 0.15 优于 risk，但 0.08 不明显。 |
| 还缺 | 多 seed 下课程是否稳定带来高密度收益。 |
| 必补实验 | risk vs proposed seeds 0/1/2，训练曲线和 curriculum stage 曲线。 |
| 可写 claim | The curriculum is designed to expose policies to harder scenarios only after sufficient task and safety performance. |
| 不能写 | Curriculum is the main reason for all improvements. |
| 审稿攻击 | “risk-only already works, curriculum is unnecessary。” |
| 防御 | 若数据支持，强调 high-density robustness；若数据不支持，降级为稳定训练机制和实验 protocol。 |

## C3 Defensive TTC/overspeed shield

| 维度 | 内容 |
|---|---|
| 一句话 | 在策略输出后加入 TTC 和超速触发的轻量制动守护，降低 high-density close-call 风险。 |
| 不是新在哪里 | runtime shielding/safety filter 已有大量工作。 |
| 新意在哪里 | 与 RAC-PPO 的训练框架结合，作为安全-效率 Pareto 分析模块。 |
| 当前证据 | ttc12/v18 seed25 density 0.15 success 0.66、collision 0.18、cost 0.20；旧模型 screen 中 ttc12/v18 collision/cost 最低。 |
| 还缺 | fixed ttc12/v18 多 seed；intervention rate；与 no shield 同协议对比。 |
| 必补实验 | ttc12/v18 seeds 24/25/26；记录 `shield_soft_rate`, `shield_hard_rate`, `overspeed_guard_rate`。 |
| 可写 claim | Defensive TTC shield improves the safety-efficiency tradeoff in dense traffic stress tests. |
| 不能写 | The shield guarantees safety. |
| 审稿攻击 | “这是规则控制，不是 RL 创新。” |
| 防御 | 定位为 hybrid intelligent control：learning policy + safety filter，符合 autonomous control 工程论文。 |

## C4 多密度未见地图评价协议

| 维度 | 内容 |
|---|---|
| 一句话 | 用 unseen map seeds 和 traffic density sweep 同时评价 success、route、collision、out-of-road、cost。 |
| 不是新在哪里 | 多场景评估不是新 benchmark。 |
| 新意在哪里 | 对你的方法来说，它把“成功率”和“安全失败模式”同时展示，避免只报 reward。 |
| 当前证据 | 14 seeds proposed，三密度结果完整。 |
| 还缺 | 对比方法同样多 seed。 |
| 可写 claim | We use a density-swept unseen-map protocol to expose both task completion and safety degradation. |
| 不能写 | We introduce a new benchmark. |

## C5 轻量可复现工程

| 维度 | 内容 |
|---|---|
| 一句话 | 在单张 RTX 4070 SUPER 上也能以 n_envs=4 顺序完成主要实验。 |
| 当前证据 | 当前硬件：RTX 4070 SUPER 12GB、12 CPU cores、31GiB RAM。 |
| 还缺 | 每类实验的耗时记录、manifest。 |
| 可写位置 | Appendix / Reproducibility details。 |
| 不能写 | Faster or more efficient than baselines unless有耗时对比。 |

## 创新点和实验的绑定关系

| 创新点 | 必须出现的实验 | 结果满足什么才算支撑 |
|---|---|---|
| 风险奖励 | baseline vs risk；wo_ttc；reward-only vs guard-only | risk 在 success/route/cost 至少两个指标优于 baseline；wo_ttc 出现 safety drop。 |
| 课程 | risk vs proposed；stage curve | proposed 在 0.15 或 stress test 下优于 risk，或 stage curve 证明稳定进入 hard。 |
| shield | no shield vs ttc12/v18；Pareto screen；intervention rate | collision/cost 明显下降，success 不大幅牺牲，intervention rate 合理。 |
| 多密度评价 | density 0/0.08/0.15 | 显示性能随 density 的边界，而不是只挑最优密度。 |

## 最终贡献写法模板

英文贡献可这样写：

1. We propose a lightweight risk-aware PPO training framework that converts TTC, lane deviation, control smoothness, and safety events into dense learning signals for MetaDrive decision control.
2. We design an outcome-gated curriculum that adjusts scenario difficulty according to route completion, success, and safety cost rather than a fixed schedule.
3. We evaluate a defensive TTC shield as a runtime safety layer and report density-swept unseen-map results that expose the safety-efficiency tradeoff.

中文解释：

- 第 1 条是主创新。
- 第 2 条是训练机制创新，但要靠实验支撑，不能夸大。
- 第 3 条是安全控制增强和实验洞察创新，最适合 ISCSIC。
