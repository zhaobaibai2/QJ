# 09 RTX 4070 SUPER / n_envs=4 实验路线图

## 当前硬件约束

远端当前检测：

- GPU: NVIDIA GeForce RTX 4070 SUPER, 12GB。
- CPU: 12 cores。
- Memory: 31GiB。
- 建议并行环境数：`n_envs=4`。

结论：

- 不建议同时开多个训练进程。
- 每次只跑 1 个 training job，`--n-envs 4`。
- evaluation 可以跟在训练后顺序跑，不要用旧的 ProcessPool 大并行评估。
- 多 seed 用队列方式顺序执行，不要用之前 n_envs=24/32 的脚本默认值。

## 先修两个运行问题

### 1. 防御脚本 Python 路径

`scripts/run_one_defensive_proposed.py` 里后处理阶段硬编码：

```python
["/root/autodl-tmp/envs/sb3/bin/python", *cmd]
```

这台机器实际 Python 是：

```bash
/home/aaa/miniconda3/envs/sb3/bin/python
```

建议把脚本改成：

```python
subprocess.run([sys.executable, *cmd], check=True)
```

否则训练和评估可能完成，但画图/报告阶段失败。

### 2. n_envs 写入 config

当前 `ExperimentConfig` 没有显式 dataclass 字段 `n_envs`，运行时动态设置，`config.json` 不记录。建议加入：

```python
n_envs: int = 1
```

否则以后无法从 config 复现“4070S 下 n_envs=4”。

## 实验优先级

### 第一优先级：补齐主对比

目标：让主表从 seed0 preliminary 变成 3-seed main result。

需要跑：

| Method | 已有 | 需要补 |
|---|---|---|
| baseline | seed0 | seed1, seed2 |
| risk | seed0 | seed1, seed2 |
| curriculum | seed0 | seed1, seed2 |
| proposed | seed0-13 | 直接复用 seed0,1,2 |

推荐输出目录：

```text
outputs/iscsic_main_nenv4/
  runs/
  evaluations/
  figures/
  logs/
```

单个训练命令模板：

```bash
cd /home/aaa/data/qj/stable-baselines3-master/risk_curriculum_metadrive
source /home/aaa/miniconda3/etc/profile.d/conda.sh
conda activate sb3
export MPLCONFIGDIR=/tmp/mpl-racrl
export CUDA_VISIBLE_DEVICES=0

python scripts/train.py \
  --variant baseline \
  --algo ppo \
  --seed 1 \
  --timesteps 1000000 \
  --horizon 1200 \
  --device cuda \
  --output-dir outputs/iscsic_main_nenv4/runs \
  --n-envs 4

python scripts/evaluate.py \
  --model outputs/iscsic_main_nenv4/runs/baseline_ppo_s1/model/final_model.zip \
  --variant baseline \
  --algo ppo \
  --seed 1 \
  --episodes 50 \
  --densities 0.00 0.08 0.15 \
  --horizon 1200 \
  --device cuda \
  --output-dir outputs/iscsic_main_nenv4/evaluations
```

建议顺序：

1. `risk seed1`
2. `risk seed2`
3. `baseline seed1`
4. `baseline seed2`
5. `curriculum seed1`
6. `curriculum seed2`

原因：

- risk 是当前主增益来源，优先确认稳定性。
- baseline/curriculum 如果效果依旧低，后面可少花精力调它们。

### 第二优先级：关键消融

最低要跑：

| Ablation | seeds | 目的 |
|---|---|---|
| `proposed_wo_ttc` | 0,1,2 | 验证 TTC 风险信号。 |
| `proposed_wo_lane` | 0,1,2 | 验证车道偏离信号。 |
| `proposed_wo_smooth` | 0,1,2 | 验证控制平滑项。 |

命令模板：

```bash
python scripts/train.py \
  --variant proposed_wo_ttc \
  --algo ppo \
  --seed 0 \
  --timesteps 1000000 \
  --horizon 1200 \
  --device cuda \

python scripts/evaluate.py \
  --model outputs/iscsic_ablation_nenv4/runs/proposed_wo_ttc_ppo_s0/model/final_model.zip \
  --variant proposed_wo_ttc \
  --algo ppo \
  --seed 0 \
  --episodes 50 \
  --densities 0.00 0.08 0.15 \
  --horizon 1200 \
  --device cuda \
  --output-dir outputs/iscsic_ablation_nenv4/evaluations
```

如果时间不够：

1. 先跑 `proposed_wo_ttc` seeds 0/1/2。
2. 再跑 `proposed_wo_lane` seed0。
3. 最后跑 `proposed_wo_smooth` seed0。

### 第三优先级：Defensive RAC-PPO 固定参数补齐

推荐固定：

- `ttc_threshold=12.0`
- `target_speed=18.0`
- `horizon=1500`
- `n_envs=4`

已有：

- seed25 完整评估。
- seed24 有 model，但没有 evaluation CSV。

先评估已有 seed24：

```bash
python scripts/evaluate.py \
  --model outputs/defensive_proposed_ttc12v18_s24s25_nenv32/runs/defensive_proposed_ppo_s24/model/final_model.zip \
  --variant proposed \
  --algo ppo \
  --seed 24 \
  --episodes 50 \
  --densities 0.00 0.08 0.15 \
  --horizon 1500 \
  --device cuda \
  --output-dir outputs/defensive_proposed_ttc12v18_s24s25_nenv32/evaluations
```

注意：这个 `evaluate.py` 只会用默认 reward weights，不能自动恢复 ttc12/v18 的 reward config。更稳妥方式是写一个专用评估脚本，从 `runs/defensive_proposed_ppo_s24/config.json` 读取 config 后评估。否则评估协议可能不一致。

建议补一个 `scripts/evaluate_from_config.py`：

- 输入 `--config-json`
- 输入 `--model`
- 恢复 `ExperimentConfig` 和 `RewardWeights`
- 输出 CSV

### 第四优先级：拆分 reward 和 guard

这是审稿最容易抓的问题。建议新增两个开关：

```python
use_risk_reward: bool = True
use_action_guard: bool = True
```

然后跑：

| Variant | risk reward | action guard | curriculum |
|---|---|---|---|
| PPO | no | no | no |
| Reward-only | yes | no | no |
| Guard-only | no | yes | no |
| RAC-PPO | yes | yes | yes |

如果没时间完整跑 3 seeds，至少用 seed0 做机制解释。

## 推荐 4070S 排期

不估绝对小时数，因为 MetaDrive 主要受 CPU 仿真和机器负载影响。用“批次”管理：

| Batch | 内容 | 目的 | 是否可中止 |
|---|---|---|---|
| B1 | risk seed1/2 | 确认风险奖励是否稳定 | 否 |
| B2 | baseline seed1/2 | 主表公平性 | 否 |
| B3 | curriculum seed1/2 | 课程贡献判断 | 否 |
| B4 | `wo_ttc` seed0/1/2 | 核心消融 | 否 |
| B5 | ttc12/v18 seed24 eval + seed26 train/eval | defensive 主张 | 否 |
| B6 | `wo_lane`, `wo_smooth` seed0 | 次级消融 | 可中止 |
| B7 | reward-only/guard-only seed0 | 机制拆分 | 强烈建议 |

## 停止规则

不要无限调参。建议设置硬边界：

| 情况 | 动作 |
|---|---|
| risk 三种子仍明显优于 baseline | 固定 risk reward，不再改 reward 大框架。 |
| proposed 不优于 risk | 课程贡献降级，不继续为了“证明课程”调参。 |
| ttc12/v18 三种子高密度 success < 0.55 或 collision > 0.30 | defensive 不进 abstract，只进 discussion。 |
| `wo_ttc` 与 full 几乎相同 | TTC claim 降级，检查 action guard 是否掩盖 reward。 |
| 任何设置只在单 seed 提升 | 标为 exploratory，不进主结论。 |
