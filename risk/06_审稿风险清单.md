# 06 审稿风险清单

## 总体建议

按当前材料，审稿结论大概率不是“想法不行”，而是“实验和声明还没对齐”。只要把 claim 降到证据能支撑的范围，并补齐主对比/消融，ISCSIC 级别是可行的。

## 最高风险问题

### R1: Baseline 不充分

审稿人可能说：

> 只比较 PPO 变体不足以证明方法有效，尤其缺少 safe RL 或 runtime shield baseline。

当前证据：

- seed0 有 baseline/risk/curriculum/proposed。
- proposed 有 14 seeds。
- baseline/risk/curriculum 没有同等多 seed。
- SAC 接口存在但结果缺失。

防御策略：

1. 补 baseline/risk/curriculum 三种子。
2. 添加 `shield_only` 或 `PPO + TTC guard without risk curriculum`。
3. 若不补 SAC，论文中删掉 SAC 对比承诺。

严重级别：CRITICAL if not fixed。

### R2: Reward shaping 与 action guard 混淆

审稿人可能说：

> 你的 risk_reward 既改变 reward，又改变动作，因此无法知道提升来自学习还是规则控制。

当前证据：

- `RiskAwareMetaDriveWrapper.step()` 中 `self.exp.risk_reward` 会同时启用 TTC/overspeed guard 和 reward shaping。

防御策略：

1. 加两个开关：`risk_reward` 和 `action_guard`。
2. 做四组：
   - PPO
   - PPO + reward only
   - PPO + guard only
   - PPO + reward + curriculum + guard

严重级别：MAJOR，若主打 shield 则接近 CRITICAL。

### R3: 课程学习贡献不清

审稿人可能说：

> Risk-only 已经与 proposed 接近，课程模块贡献不明显。

当前证据：

- seed0 density 0.08: risk success 0.740，proposed success 0.740。
- seed0 density 0.15: risk 0.420，proposed 0.480。

防御策略：

1. 用三种子验证 high density 下课程是否稳定提升。
2. 若提升弱，改写贡献：课程是训练稳定化/难度覆盖机制，不作为最大性能来源。
3. 展示课程阶段曲线和进入 hard stage 的时间。

严重级别：MAJOR。

### R4: 高密度结果仍低

审稿人可能说：

> density 0.15 下 success 约 0.47，collision 约 0.41，安全性不够。

防御策略：

1. 明确把 density 0.15 写为 stress test，不是主任务。
2. 把 Defensive RAC-PPO 作为 high-density 改进模块。
3. 用 failure analysis 说明高密度是后续工作，而不是掩盖失败。

严重级别：MAJOR，但诚实写法可降为 limitation。

### R5: 结果汇总不一致

审稿人可能说：

> 论文表格、代码默认参数和真实 run config 对不上。

当前证据：

- `config.py` 默认 stages 是 0.10/0.22。
- run config 是 0.08/0.15。
- `final_paper_results` 漏 seed5-13。
- `paper/main_zh.tex` 写了未完成实验。

防御策略：

1. 以 run `config.json` 生成 final table。
2. 论文附录放 protocol table。
3. 源码默认值同步到最终协议。

严重级别：CRITICAL if unchanged。

## 中等风险问题

| 问题 | 风险 | 防御 |
|---|---|---|
| only simulation | 不能声称真实部署 | 限定为 MetaDrive 仿真决策控制。 |
| no formal safety guarantee | shield 是启发式 | 写 heuristic defensive shield，不写 formal verification。 |
| high seed count only for proposed | 对比不公平 | 主表必须同 seed 数，14 seeds 可以做额外稳定性分析。 |
| no intervention rate | shield 机制不可解释 | 新增日志和表格。 |
| no statistical test | mean/std 不够 | 使用 seed-level mean±std；必要时 bootstrap CI。 |
| English paper not ready | ISCSIC 要英文 | 先产英文 IEEE 6-8 页，不要提交中文稿。 |

## 推荐审稿式 verdict

当前版本：

> Accept with Revisions

理由：

- 选题和 venue fit 是正面的。
- 工程和数据基础较好。
- 核心方法有清楚模块。
- 但实验矩阵、消融、最终汇总和 claim 边界还不达投稿状态。

如果完成 P0：

> Ready for ISCSIC submission

如果不补 P0：

> High-risk submission, likely rejected for insufficient evaluation.

## 投稿前检查表

### 内容

- [ ] 英文 IEEE 模板。
- [ ] 摘要包含 problem、method、result、limitation，不夸张。
- [ ] Introduction 中贡献不超过 3 条。
- [ ] Related Work 至少 12 篇可核验文献。
- [ ] Method 明确 reward、curriculum、shield 的区别。
- [ ] Experiment 明确 train/test seeds、density、horizon、timesteps、episodes。
- [ ] 主表为同协议多 seed。
- [ ] 消融至少包括 TTC 和 action guard。
- [ ] 高密度只写 stress test。
- [ ] Limitations 单独成段。

### 代码和结果

- [ ] final results 脚本可一键重建表。
- [ ] 每个 run 有 config.json。
- [ ] config.json 记录 n_envs 或另有 manifest。
- [ ] CSV、figures、tables 路径在论文中可追踪。
- [ ] 没有引用不存在的 `outputs/ablation` 图。
- [ ] 没有把筛查结果写成最终 benchmark。

### 图表

- [ ] Main performance table: success/route/collision/out/cost。
- [ ] Robustness figure: density sweep。
- [ ] Ablation figure/table。
- [ ] Shield Pareto figure/table。
- [ ] Training curve and curriculum stage。
- [ ] Qualitative trajectory/failure case。

## 最终建议

论文不要追求“看起来结果最高”，而要追求“证据链完整”。ISCSIC 更可能接受一个边界清楚、实验矩阵完整的安全控制工程论文，而不是一个声称很大但对比和消融不够的 RL 论文。
